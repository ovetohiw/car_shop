### Проблема и цель

- Проблема: нет работающего онлайн-магазина для продажи автомобилей и связанных запчастей с конфигурацией заказа, учётом заказов и кабинетом исполнения.
- Цель: поднять MVP стенд (Docker Compose): каталог авто с фото, раздел запчастей, auth, конфигуратор с расчётом цены на сервере, заказы у покупателя и у staff с эмуляцией отправки на исполнение.
- Что должно измениться: пользователь открывает UI на порту 8080, может зарегистрироваться/войти, собрать конфигурацию авто или заказать запчасти, оформить заказ; staff видит все заказы и двигает статусы эмуляции.

### Скоуп

В скоупе:

- Каталог автомобилей с изображениями
- Отдельный раздел запчастей
- Регистрация, вход, выход; JWT-защита API; роли `customer` и `staff`
- Конфигуратор: модель, комплектация, цвет, доп. услуги; пересчёт итоговой стоимости на backend
- Оформление заказа автомобиля и/или запчастей
- Кабинет покупателя: свои заказы
- Staff-кабинет: все заказы; эмуляция исполнения статусами (`new` → `submitted` → `in_fulfillment` → `completed` / `cancelled`)
- Health-check backend
- Демо-сиды (каталог, картинки, staff-учётка)
- Развёртывание всей инфраструктуры через docker-compose: frontend :8080, backend :8081, Oracle :1521

Вне скоупа:

- Реальные платежи и банковские шлюзы
- Доставка / логистика
- OAuth через соцсети
- Админ-CRUD каталога в UI
- Мультивалютность
- Мобильные приложения
- Микросервисы
- Локальный запуск без Docker как основной путь DoD

### Поведение и контракт

Наблюдаемое поведение: вход, выход, отказ. Без привязки к внутренней реализации.

- Счастливый путь:
  - Гость открывает `http://localhost:8080`, видит каталог авто с фото и раздел запчастей.
  - Пользователь регистрируется и входит; оформляет конфигурацию авто (модель, комплектация, цвет, доп. услуги) и/или заказ запчастей; видит итоговую стоимость, согласованную с сервером; заказ появляется в «Мои заказы».
  - Staff входит в спец-учётку, видит все заказы и последовательно меняет статусы эмуляции исполнения.
- Ошибки и отказы:
  - Без auth создание заказа недоступно (401/редирект на вход).
  - Не-staff получает отказ (403) на staff-эндпоинты и staff-страницы.
  - Подмена цены / роли / чужого userId с клиента отвергается; итог считает только сервер.
  - Невалидная конфигурация (несуществующая модель/опция) — явный отказ без создания заказа.
- Границы и контракт:
  - UI: порт 8080; API: порт 8081; Oracle: порт 1521 — после `docker compose up`.
  - Цены и `total` не доверяются клиенту.
  - Платежей нет: заказ = заявка с рассчитанной стоимостью.
